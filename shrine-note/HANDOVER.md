## 3. 神社を増やす手順（今回の流れ）
1. 追加する神社を決める（すでに載せた神様とつながる社を優先）
2. 調査エージェント（general-purpose・sonnet）を、3〜4社ごとに並行起動。指示は `作業資料\スクリプト\SPEC.md` を読ませる。結果は `{班}.json`
3. `作業資料\スクリプト\merge_final2.py`（班の文字・パスを直して使う）で検査して取り込む。検査内容: 重複ID・出典の参照切れ・親子の循環・古事記/日本書紀の引用を `作業資料\古典テキスト\` の原文と機械照合（一致しない引用は削除）・`when` の有無

5. `README.md`（神社の一覧）と `VERIFY_TODO.md` を更新 → PR → マージ → 公開版で確認（Pagesは数分遅れる）

## 4. 作業環境の注意
- 作業ツリー: `C:\dev\wt-shrine`（`ns-factory` の worktree・OneDriveの外）。毎回 `git fetch` → `origin/main` から新しいブランチ → 編集 → PR → マージ。`git add -A` は使わず、対象を明示
- 確認用サーバー: `py -m http.server 8795 --bind 127.0.0.1`（Bash の run_in_background）。終わったら `http.server 8795` のプロセスを止める。ターミナルツールは起動に失敗することがある
- ブラウザ枠（Claude の built-in browser）は、前面でないと描画（rAF）が止まる。確認は「JS実行 → スクリーンショット」を交互に行うと進む。公開版の確認は `preview_start` に `url` を渡して開き直す
- 公開版は数分遅れる。`curl` で `shrines.json` や `map.js` の新しい文字列を確認してから見る。ブラウザは JSON を覚えているので、強制再読み込みを案内する
- SNS: 投稿は要承認。予約キュー（GAS `snsqueue_add`）は画像1枚まで・冪等でない・再送しない。ハッシュタグは本文に無い語だけ。専門用語を使わない（平易な言葉）
- 道路の経路は OSRM 公開サーバー（無料・デモ用）。混むと失敗するため、必要なら Cloudflare Worker＋無料枠（方式B）か有料API（方式C）へ。現在地は同意画面を通したときだけ送る
