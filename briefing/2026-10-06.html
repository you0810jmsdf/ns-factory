現状分析CAD運用は体制整備段階

  1. 組木の接合パターン3種をスケッチして記録する
  2. 治具か型紙か製品か、設計目的を絞ってからツールを選ぶ
  3. 変更時は保存場所と確認方法を業務日誌に残す

CASE 02 ／ 販売幕僚

楽天アフィ準備の3点セット

要点SNS発信を仕組み化する準備術

楽天アフィリエイトで稼ぐための準備として、①自己紹介を3行で作る②投稿のパターンを5つ用意する③紹介する商品を10個決めておく、という3点セットが紹介されていました。型を先に決めておけば毎回考える手間が減り、投稿が速く作れるようになります。

現状分析商品紹介の型は一部ある

  • 商品ページは「結論→体験→弱点→おすすめ」の順と決まっている
  • ボタン文言は「動詞＋得られるもの」にする指針がある
  • Instagram・Threads・Xのプロフィール文や投稿型のテンプレートは記録なし

図解

自己紹介3行を作る → 投稿型5パターンを決める → 紹介商品10個をリスト化 → 型に沿って投稿を量産

提言SNSの自己紹介と投稿テンプレを先に作る

  1. Instagram・Threads・Xのプロフィールを特化・体験・メリットの3行で書く
  2. 悩み解決・失敗談・比較・ビフォーアフター・緊急性の5型テンプレを用意する
  3. システム手帳・型紙PDF・リフィルPDFなど紹介する商品10個を先にリスト化する
  4. 既存の「結論→体験→弱点→おすすめ」の順と組み合わせて投稿時間を短縮する
いま投稿のたびに内容をゼロから考えている
→
実行後型に当てはめるだけで1投稿5分で作れる

CASE 04 ／ デジタル幕僚

AI作業を4役+5ステップで設計

要点AIは4役+5手順で安全に働かせる

AIに仕事を全部まかせて休みなく働かせると、大きな失敗につながることがあります。そこで『見張り役・作る役・確認役・実行役』の4つに分け、5つ作業したら一度立ち止まって確認する仕組みにすると、安定してAIに任せられるという話です。

現状分析ルーターはあるが役割分担は未整備

  • 請求書発行システムのCode.gsはdoGet/doPostで処理を振り分けるルーター構造を持つ。
  • AI共通ブリーフ.mdをClaude/Codex共通の入口として整備済み（2026-09-04）。
  • 直近の変更記録は在庫登録やサイト修正など単発の記載のみで、役割分担や段階確認の仕組みは見当たらない。

図解

見張り役:情報を集める → 作る役:成果物を作る → 確認役:ズレを確認 → 実行役:反映・送信

提言AI作業に4役+5ステップ型を導入

  1. 自動化ツール更新を見張り役・作る役・確認役・実行役の4役に分けて進める
  2. 5ステップごとにチェックポイントを入れ、誤反映や暴走を防ぐ
  3. 許可(自動)・要確認・禁止の3段階の権限をGAS連携作業に設定する
  4. まずはBillingなど定型作業から試し、効果を見て他ツールにも広げる
いまAI作業は一人のAIに任せきりで進めている
→
実行後役割分担と5ステップ確認で安全に自動化できる

CASE 05 ／ デジタル幕僚

Claude 3モデル使い分け設定

要点AIを3役に分けて使うしくみ

Claude Codeという開発AIを、計画係（Opus）・作業係（Sonnet）・疑い深い相談役（Fable）の3役に分けて使う設定です。同じエラーが2回続いたら相談役が出動する仕組みで、コストを抑えつつ品質を保てます。

現状分析AI役割分担は接客で先行運用

  • AI接客は実務相談用Haikuと雑談用Geminiに役割分担済み、コードで自動振り分け中。
  • 自動売買の検証ではClaude・Gemini等複数AIを使い分ける設計が進行中（要作り直し）。
  • 開発作業そのものをOpus/Sonnet/Fableで役割分担する運用はまだ記録なし。

図解

Opusが計画 → Sonnetが実行 → エラー2回でFableが相談 → Opusが最終判断

提言開発AIにも3役の使い分けを試す

  1. CLAUDE.mdにFable相談設定を追加し、同じエラー2回で自動相談させる
  2. まずは/model opusplanで計画をOpus・実行をSonnetに分ける簡易運用から始める
  3. 無料アプリ群やEC連携ツールの改修作業にこの役割分担を試す
  4. 既存のAI接客振り分けロジックとの相性を見ながら段階導入する
いま開発作業はモデルを分けずに一括で進めている
→
実行後計画・実行・相談を役割ごとのモデルで分担しコストを抑えられる

出典：Threads の投稿

CASE 06 ／ デジタル幕僚

FFmpeg＋AIによる動画自動処理

要点動画編集をAIが自動でやってくれる道具

FFmpegという動画編集ソフトをAI（Claude CodeやCodexなど）が直接操作できるようにする仕組みです。ネット接続やアカウント登録が不要で、パソコンの中だけで動画のカット・字幕付け・音量調整などを自動でできます。先に素材を確認してから作業し、終わったら結果も自動でチェックします。

現状分析動画自動化は検討候補段階

  • 講座動画・SNS動画の編集自動化はClaude Code＋video-use／Remotionを比較中（未検証）
  • 動画編集・字幕の無料候補としてOpenCutなども検討中（未検証）
  • 導入する場合はOneDriveの外に置く方針がある
  • 読み上げ音声を本人の声へ替える候補も別途計測中

図解

素材を確認(probe) → カット・字幕を自動処理 → 結果を自動検証 → 講座・SNS動画として公開

提言ffmpeg-skillをGitHubで確認し試験導入

  1. GitHubで中身とライセンスを確認する
  2. npx実行時に通信や外部送信がないか確認する
  3. 講座動画の後処理（カット・字幕）で小さく試す
  4. 既存のvideo-use／Remotion検討と比較して選ぶ

→
実行後ローカルでAIがカット・字幕まで自動処理できる可能性

現状分析正本は整備済み、再編成は未着手

  • 台帳・セッション共有・業務日誌など正本の種類も整理済み

CLAUDE.mdの構成を確認 → 用途別ファイルにAGENTS.md型で再 → 権限4行で承認範囲を明確化 → 外部スタッフへ品質を保って引き継ぎ

提言CLAUDE.mdをAGENTS.md型に再編成する

  1. CLAUDE.mdの中身を置き場所ルールに沿って棚卸しする
