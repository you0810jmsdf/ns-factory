CASE 01 ／ 作戦幕僚

Claude Code Modsの事前チェック機能

要点Claude Codeに「安全装置」を追加

Claude Codeという作業AIに、自分専用の機能を足せる仕組み「Mods」が登場しました。中でも注目は、危ない操作を実行する前に自動で止めたり、通知を出したりする機能です。人が見ていなくても、おかしな操作を防げるようになります。

現状分析運用ルールあり・自動停止は未整備

  • GitHub pushの自動許可や課金を伴う処置の事前見積など、運用ルールは文書化済み
  • APIキーを使うカレンダー登録など、人手の確認に頼る処理が残っている
  • 危険操作を実行前に自動で止める仕組み（フック）は未導入

図解

戦略指示書の作業指示 → 危険操作の実行直前 → Modsが自動で一旦停止 → 事業主が確認・許可

提言Mods⑤を既存の運用ルールに組み込む検討を

  1. ⑤の仕様を確認し、既存のCLAUDE.md運用ルールとの互換性を検討する
  2. GitHub push・課金処理など危険操作の自動中断に使えないか試す
  3. 夜間や自動実行タスクの安全確認に活用できないか検証する
  4. まず小さな操作で試し、問題なければ本番運用に広げる
いま危険操作のチェックは人手ルールのみに頼っている
→
実行後危険操作を実行前に自動で検知・中断できる可能性がある

CASE 02 ／ デジタル幕僚

地域ビジネスWebサイト穴埋めプロンプト

要点穴埋め式サイト作成プロンプトの型

「【都市】にある【業種】の【店名】のためにWebサイトを作って」のように、空欄を埋めるだけでサイト作成の指示文が作れる型が紹介されました。全6項目のうち、確認できたのは冒頭部分のみです。

現状分析サイト管理は運用中、テンプレ化は未着手

  • 自社サイトやGAS連携、見積・カラーシミュレーターなどのECツールを管理している
  • 販売幕僚からサイト管理、後方幕僚から無料アプリ管理を引き継いだばかり
  • Web幅・グリッドやスマホ本文基準など、自サイト点検の物差しは資料にある
  • 提携先や地域店舗向けサイト制作の項目洗い出しテンプレはまだ資料にない

図解

穴埋めプロンプト取得 → 全6項目の洗い出し → 自社テンプレに【】形式で組込み → 自社・提携先サイト制作へ活用

提言穴埋めプロンプトを自社テンプレに組み込む

  1. 確認できた冒頭項目を自社テンプレに【都市】【業種】形式で反映
  2. 提携工房や地域団体のサイト制作依頼時の項目洗い出しに使う
  3. 未確認の残り項目を元投稿で確認し、社内資料に追記する
いまサイト制作時に入れる項目を都度ゼロから考えている
→
実行後穴埋め式テンプレで必要項目を即座に洗い出せる

CASE 03 ／ デジタル幕僚

Claude Code神設定セットアップ

要点Claude Codeの神設定プロンプト登場

Claude Code（AIにパソコン作業を頼める仕組み）に1回貼るだけで、指示書・作業手順・確認役・最終チェックの5点セットを自動で作ってもらえる無料プロンプトが公開されました。長い説明文を毎回書く手間が減るのが利点です。

現状分析引き継ぎ書が長文化している

  • デジタル幕僚の引き継ぎ書.mdにシステム詳細や知見が長文で蓄積されている
  • プロジェクト台帳.mdはClaude・Codex・人間が同じ入口から探せる仕組みを目指している
  • GMOコイン自動売買基盤など個別プロジェクトの検出事項も長文で記録されている

図解

長い引き継ぎ書・台帳をそのまま読ませる → セットアッププロンプトを1回実行 → 指示書・手順・確認役・検査の5点セットが → 次回の委譲作業で再利用

提言次回の委譲時にセットアッププロンプトを試す

  1. 無料配布のセットアッププロンプトを入手し内容を確認する
  2. 作業フォルダで1回実行し、生成される設定ファイル一式を確認する
  3. 引き継ぎ書.mdの長文部分を短い設定ファイルに分割できないか検証する
  4. GAS開発以外に記事作成やリサーチ案件でも同じ型を使えるか試す
いま引き継ぎ書.mdに全情報を詰め込み毎回読ませ直している
→
実行後短い設定ファイル一式で指示・手順・検査が自動的に揃う

CASE 04 ／ デジタル幕僚

AI注意力管理：夜→翌朝通知フロー

要点AIが夜に情報整理し朝に通知

OpenAIの新機能「dots」はCEO本人も使っている仕組みです。毎晩届いた情報を全部読み、重要度を整理し、緊急事項を抜き出して、翌朝「今日いちばん見るべきもの」だけを知らせてくれます。使うほど何を重視すべきか学習していくのも特徴です。

現状分析週次レビューはあるが夜間自動化なし

  • 現状は週［数値］（毎週月曜8時）のタスクで前週の知見をまとめ、事業主承認後に追記する運用。
  • 毎晩情報をレビューし翌朝だけ通知する仕組みは社内資料に記録なし。
  • 重要度を自動で学習・判断する仕組みも導入されていない。

図解

情報が届く → 夜間にAIが整理 → 優先度をまとめる → 翌朝ダイジェスト通知

提言dots型の夜間→朝ダイジェストを試す

  1. dotsや別ツールで夜間レビュー→翌朝通知のプロトタイプを作ってみる
  2. 既存の週次反映フローを毎日版に広げ、優先度学習を試す
  3. 通知内容を「今日最優先で見るべきもの」だけに絞る設計にする
  4. 導入前に課金体系など未確認点を実画面で確認する
いま週［数値］、月曜朝だけ知見をまとめ承認を待つ
→
実行後毎晩自動整理され、翌朝最優先事項だけ届く
