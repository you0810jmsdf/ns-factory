CASE 01 ／ 作戦幕僚

AI時代の仕事の線引き

要点CADの仕事、AIに残る部分は？

図面を写す「トレース」はAIが得意になってきた一方、描かれていない寸法や仕様を決める「判断」の仕事は人にしかできない、という話です。写す作業と決める作業を分けて考えることが鍵になります。

現状分析型紙CADはAI活用が構想段階

  • 型紙・CAD資産はバックアップ維持が中心で、AIトレース活用の運用実績はまだない
  • WEB版レザークラフトCAD×AIの連携実例を、型紙自動生成の参考として記録している
  • CAD設計は何を作りたいか事業主に確認してからツールを選ぶ方針がある
  • 型紙は寸法精度が重要で、変更後は印刷・表示寸法の確認が必須とされている

図解

AIに任せる（写す作業）

  • 写真から線を起こす
  • 規格化された形の清書
  • 繰り返しパターンの複製

自分が担う（決める作業）

  • サイズ・寸法の最終決定
  • 仕様・用途に合わせた調整
  • 寸法精度の確認・検品

提言型紙制作を「トレース」と「寸法決定」に分けて試す

  1. 型紙制作工程をAIトレースと自分の寸法決定に分離して試運用する
  2. AIには下書き線の起こしを任せ、最終寸法は自分で判断・確定させる
  3. 型紙変更後は必ず印刷・表示寸法を自分の目で確認する
  4. WEB版CAD×AI連携の情報を型紙自動生成構想の参考として記録しておく
いま型紙制作はトレースから寸法決定まで全て手作業で通している
→
実行後トレースはAI活用、浮いた時間を寸法決定・品質確認に回せる

CASE 02 ／ 販売幕僚

商品名×購入KWチェック表

要点商品タイトルにキーワードを足す工夫

ネット記事のタイトルに「口コミ・比較・おすすめ」などお客さんが検索しそうな言葉を組み合わせると見つけてもらいやすくなる、という話。ただしタイトルだけ変えて中身をコピペするのはNGで、それぞれ内容のある記事にする必要がある。

現状分析キーワード掛け合わせは未着手

  • 商品ページの並べ方「結論→体験→弱点→おすすめ」の順は既に記録済み
  • 商品名×購入系キーワードの一覧表はまだ作られていない
  • 商品マスターシートには商品名の列はあるが検索キーワード専用の列はない

図解

商品名（システム手帳） → 購入系キーワードを掛け合わせ → タイトル案を複数作成 → EC・ブログに掲載

提言手帳の商品タイトルにキーワード掛け合わせを試す

  1. システム手帳の商品ページタイトルに「レビュー・比較・革の種類」を掛け合わせた案を3本作る
  2. 既存の「結論→体験→弱点→おすすめ」の構成に沿って本文を書き分け、コピペ量産を避ける
  3. 商品マスターシートに検索キーワード列を追加し一覧表として管理する
いまタイトルは商品名だけで検索キーワードがない
→
実行後レビュー・比較等を掛け合わせたタイトル案を複数用意できる

CASE 03 ／ 販売幕僚

案件選定の絞り込み基準

要点副業の案件選びを5段階で絞る方法

アフィリエイト案件は数が多すぎて迷いがち。①ASPに10社登録②無料で申込むだけで報酬が出る案件だけ単価順に並べる③単価5千円以上で悩みが一言の案件を1つ選ぶ④それだけ記事化⑤成果が出たら次に進む、という選び方が紹介されていました。

現状分析副業候補は複数、絞込基準なし

  • 副事業候補として講座型動画・海外販路・スターターキット同梱など複数の案が出ている段階です
  • AI業務ツール講座では視聴回数などの数値基準で判定する例があり、基準づくりの前例があります
  • 単価や申込条件で候補を絞り込む明文化されたルールはまだ社内資料に見当たりません

図解

候補リストを作る → 単価5千円以上×無料申込で絞る → 悩みが一言の案件を1つ選ぶ → 1つだけ試し、成果後に次へ

提言副業候補に3条件フィルターを通す

  1. 副事業候補リストに「単価5千円以上」の列を追加して絞り込む
  2. 残った候補のうち「悩みが一言で言える」ものを1つだけ選ぶ
  3. 選んだ1件だけ検証し、成果が出てから次の候補に進む
  4. いま挙がっている候補3件をこの基準で並べ替えてみる
いま副業候補を基準なく複数同時に検討している
→
実行後3条件で1つに絞り、順番に試せる状態になる

CASE 04 ／ 販売幕僚

楽天ROOM週次改善ループ

要点AIで商品選び→投稿を毎週回す型

楽天ROOMという商品紹介サービスで、AIに「5千円くらいで悩みが一言で言える商品」を選ばせ、悩みごとに投稿文を作らせて毎日予約投稿。週1回、売れた商品の共通点をAIに聞いて来週の商品に入れ替える、という回し方の紹介です。

現状分析週次で数字を見る仕組み未導入

  • 商品ページの並べ方やボタン文言の知見はあるが、週次で数字を見て入替える仕組みはまだない
  • EC運用はminne・Creema等の複数チャネルで手作業フローが中心
  • SNS発信（Instagram・Threads・X）の運用状況は社内資料に記載がない

図解

人気商品/投稿データを取得 → AIに悩みを複数案出させる → 悩みごとに投稿文を量産・予約 → 週1で数字を見て入替

提言AIで悩み展開→投稿量産の型を試す

  1. 人気商品やよく出る質問をAIに見せ、悩みを複数案出させてみる
  2. 悩み1つにつき投稿文を1本作らせ、SNSへの予約投稿に使う
  3. 週1回、反応の良かった投稿の共通点をAIに分析させる
  4. 型紙PDF・リフィルPDFの訴求文づくりにもこの型を応用できないか検討
いま投稿ネタは都度考え、数字分析はしていない
→
実行後AIが悩み展開→投稿量産、週次で入替できる

現状分析関連する記録なし

CASE 06 ／ 広報幕僚

Threads投稿の型化

要点Threadsが伸びる3つのコツ

SNSのThreadsで投稿が伸びやすくなる型が紹介されていました。①その投稿だけで分かるように作る②「誰向けか」をはじめに書く③投稿する時間を決めて直後の反応を見る、という3つです。

現状分析型は未導入、土台はあり

  • Threads・Instagram・X・LINEで発信中、投稿は一部自動・一部手動運用
  • 投稿カテゴリと頻度は方針化済みだがタグ整備は完了している
  • 1行目に属性ワードを入れる運用や時間帯固定は資料に記載なし

図解

1行目に属性ワード → 初見前提で完結 → 時間帯を固定して投稿 → 直後1時間の反応確認

提言Threads投稿にこの型を試す

  1. 1行目に「システム手帳ユーザー向け」など属性ワードを入れる
  2. 各投稿を初見前提で作り、前提共有を省いて完結させる
  3. 投稿時間帯を固定し、直後1時間の反応をチェックする
  4. 反応が良ければInstagramなど他SNSにも型を広げる
いま投稿は属性ワードなし・時間帯もばらばら
→
実行後1行目に属性ワード、決めた時間帯に投稿
