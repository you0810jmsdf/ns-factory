CASE 01 ／ 販売幕僚

広告成果の掛け算分析型

要点広告の成果を3段階に分けて見る

広告の結果は「表示→クリック→申込」の掛け算で決まる、という話です。表示1万回・クリック率1%なら100クリック、申込率2%なら申込2件。どの段階が弱いかを分けて見れば、直す場所が分かります。

現状分析段階別の数字分析は記録なし

  • 商品ページは「結論→体験→弱点→おすすめ」の順に並べる方針がある
  • ボタン文言は「動詞＋得られるもの」、スマホは44px以上にする方針がある
  • 講座告知はThreads/Instagram/FacebookへSNS予約投稿する運用がある
  • 表示数・クリック率・申込率を段階別に数字で分ける運用は社内資料に記録なし

図解

Creema広告の表示数を集計 → クリック数を集計 → 購入数を集計 → どの段階が弱いか特定する

提言広告成果を3段階に分けて記録する

  1. Creema広告の過去3ヶ月の表示数・クリック数・購入数を段階別に集計する
  2. クリック率が低ければ広告文・画像を見直し、申込率が低ければ商品ページを見直す
  3. EC商品ページも閲覧数→カート投入→購入の段階で数字を分けて改善点を探す
  4. 講座集客も予告動画の再生数→申込数の2段階でメモして集客の弱点を探す
いま広告の数字はまとめて見ていて、どこが弱いか分からない
→
実行後表示・クリック・申込の3段階で見て、直す場所がすぐ分かる

出典：Threads の投稿

CASE 02 ／ 販売幕僚

アフィリで単価帯・サイト型を逆算

要点アフィリは単価帯から逆算

アフィリエイト（他社商品を紹介して売れたら報酬がもらえる仕組み）の連載記事。月1万円の報酬には月100万円の売上が必要で、1,000円の商品だと1,000個売る必要があるが、1万〜5万円の商品なら100〜20個で済む。だから単価帯とサイトの型を先に決めようという内容。

現状分析アフィリ運用は記録なし

  • 型紙PDF販売の注意点に『アフィリや外部リンクは表示・表記の確認が必要』と記録あり
  • 商品ページは『結論→体験→弱点→おすすめ』の順が良いという知見は既に追記済み
  • 材料ガイドは購入先・価格・在庫の変動を前提に書く方針（工具・革紹介にも関連しうる）
  • 単価帯やサイト型をどう選ぶかという検討・実施の記録はまだない

図解

bars

  • {'label': '1,000円の商品', 'value': 1000.0}
  • {'label': '1万円の商品', 'value': 100.0}
  • {'label': '5万円の商品', 'value': 20.0}

提言工具・革紹介はカテゴリ特化型から着手

  1. 単価1万〜5万円の工具・革関連商品を紹介記事の軸に据える
  2. 商品ページは『結論→体験→弱点→おすすめ』の型で統一する
  3. Amazon提携は記事数を増やしてから申し込む
  4. 型紙PDF紹介記事にもアフィリエイトの表示・表記ルールを確認する
いま紹介記事の商品単価帯・サイト型が未検討
→
実行後1万〜［数値］帯・カテゴリ特化型で方針が決まる

CASE 03 ／ 広報幕僚

全取引公開型の発信設計

要点勝ち負け全部見せる発信

SNSである人が、自動売買の結果を良い時も悪い時も全部公開するアカウントを作りました。「まず1000回やってみる」と目標の回数を先に決め、数字で続きを見せていくやり方です。

現状分析数字先決め型の発信は未着手

  • Threadsは自動投稿、Instagram・Xは手動投稿で、ハッシュタグや投稿カテゴリの方針は整備済み
  • LINEスタンプの残り枠をSNSで公募する企画が進行中で、目標件数を先に決める発想に近い
  • 制作数や販売数などの数字を継続公開する発信の記録は社内資料に見当たらない

図解

目標件数を決める → 制作・販売の数字を記録 → 良い結果も悪い結果も公開 → フォロワーが見届ける

提言数字先決め型の発信をSNSに試す

  1. 型紙PDFや手帳の制作個数・受注数に目標件数を設定して公開する
  2. 完成品だけでなく失敗作・修正例も記録し、勝ち負け全部見せる姿勢で信頼を作る
  3. Threadsの固定ポストに目標件数を明記し、本文は価値提供に専念する型を使う
  4. 月1回、進捗数字をまとめて振り返り投稿にする
いま完成品の紹介だけで制作過程や数字は非公開
→
実行後目標件数と進捗数字を継続公開し、見届けてもらえる発信になる

CASE 04 ／ デジタル幕僚

引き継ぎ書で切替コスト1/15

要点AIモデル切替前に引き継ぎメモ

AI（Claude）で安いモデルから賢いモデルに切り替えると、それまでの会話を全部読み直すため料金が跳ね上がります。切り替える前に短い『引き継ぎ書』を書いてから一度リセットすると、この無駄な費用を減らせるという工夫です。

現状分析GMO自動売買で試験導入中

  • モデル切替時の引き継ぎ書運用(HANDOFF)は現在GMOコイン自動売買で試験導入中
  • 効果が確認できたらデジタル幕僚の長時間セッションにも展開を検討する段階
  • サイト大規模改修など長時間作業への正式展開はまだこれから

図解

bars

  • {'label': '引き継ぎなし切替', 'value': 1.5}
  • {'label': '引き継ぎ書あり切替', 'value': 0.1}

提言長時間作業にHANDOFF運用を広げる

  1. サイト大規模改修など長時間作業でHANDOFF運用を試す
  2. GMOコイン自動売買の試験結果を見てから展開判断する
  3. 切替前に/handoffで引き継ぎ書を作る運用を定着させる
いまモデル切替のたび高コストの再読み込みが発生
→
実行後引き継ぎ書を作ってから切替、コストを抑えられる

CASE 05 ／ デジタル幕僚

Opus+Jev分業で判定AI設計

要点2つのAIを分業させる新手法

Xで話題の投稿。「Opus 5.5」という高性能AIと「Jev」という別のAIを組み合わせると、Opus単体で動かすより200倍速く400倍安くできると主張されています。ただし本当に同じ精度が出るかは未検証との指摘もあります。

現状分析AIの役割分担は既に一部運用中

  • 実務相談はHaiku・雑談はGeminiと役割分担し振り分けロジックで判定済み
  • 振り分けで判定が不一致の場合は安全側（雑談AI）に流す運用
  • GMOコイン自動売買でも相場の局面（上昇・下降・横ばい）をAIで判定する仕組みを構築中

図解

問い合わせ・メールが届く → 軽量AIが内容を振り分け判定 → 簡単な内容→軽量AIが処理 → 複雑な内容→本格AIへ引き継ぎ

提言軽量AI×本格AIの分業を仕分けに応用検討

  1. メール仕分けやボット判定に軽量AI＋本格AIの2段構えを試せないか検討する
  2. 既存のAI接客振り分けロジックの精度改善にOpus+Jev的な分業思想を参考にする
  3. 速度・コストの主張は未検証な面もあるため、まずは参考知識として蓄積する
いま判定は1種類のAIで一括処理している
→
実行後簡単な判定は軽量AI、難しい判定だけ本格AIに任せられる

CASE 06 ／ デジタル幕僚

Codex Auto-review無料化

要点Codexの自動審査が無料に

AIプログラム作成ツール「Codex」で、危険な操作だけ別のAIがチェックして止めてくれる機能が無料になりました。これまでは人が毎回『実行していいよ』のボタンを押す必要がありましたが、その手間が減る仕組みです。

現状分析承認待ち停止が課題

  • 夜間に無人でCodexを動かすと承認待ちで止まることが選定理由に挙がっている
  • 管理画面のボタンからCodexを動かす構想があり、定型作業の自動起動を検討中
  • 現状は定型作業を対話形式で都度Codexに依頼している段階

図解

Codexが作業を実行 → 別AIが安全確認 → 危険操作だけ停止 → それ以外は自動継続

提言Auto-reviewで夜間停止を減らす

  1. 設定でAuto-reviewをONにし、夜間無人実行を試す
  2. 管理画面ボタン起動と組み合わせ定型作業を自動化する
  3. 止まった操作のログを確認し安全基準を把握する
  4. 秘密情報を扱う操作は引き続き事業主確認を残す
いま夜間の無人実行は承認待ちで止まりやすい
→
実行後危険操作だけ止まり、他は自動で継続できる
