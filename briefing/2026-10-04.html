CASE 01 ／ 作戦幕僚

ChatGPT dots で受注対応自動化設計

要点ChatGPTの新機能「dots」とは

dotsは、画面を閉じた後も自分で動き続けるAIです。メールやカレンダーと繋がり、時間や出来事をきっかけに仕事を進められます。ChatGPT Pro契約なら1体は追加料金なしで使えます。

現状分析関連する記録なし

  • 社内資料にこの案件に直接関わる記録は見つかりませんでした。

図解

問い合わせメール受信 → dotsが内容を仕分け → 担当幕僚へ自動通知 → 対応開始

提言dotsで問い合わせ仕分けを試し、受注対応を省力化する

  1. ChatGPT Pro契約の有無を確認し、追加dotsが無料で使えるか調べる
  2. 「問い合わせ仕分け→担当者通知」タスクを1つだけ試作する
  3. 返信の送信や公開は必ず事前確認するルールを決めてから任せる
  4. 試した結果を見て受注対応フロー全体への拡大を検討する
いま問い合わせは都度手動で確認し、仕分けしている
→
実行後dotsが自動で仕分けし、担当者に通知してくれる

CASE 02 ／ 作戦幕僚

Claude Code の落とし穴検知プラグイン

要点Claudeの危険サイン検知プラグイン

Claude Codeに「見張り役」の新機能が登場しました。作業内容を別のAIが横で見張り、『二重請求の恐れ』のような危ない点だけを教えてくれます。通知は『了解・相談・閉じる』の3択で返せます。1つのコマンドで有効化でき、対応バージョンとテレメトリー設定が条件です。

現状分析夜間無人の動画生成は手動対応混在

  • AI業務ツール講座の動画は夜22:30以降に無人実行し、読み上げ停止時は自動で［数値］まで再試行する運用
  • VOICEVOXが応答しないときは申し送りを出し、専用batで手動起動し直す対応も残る
  • Claude/Codex共通の上位方針としてCLAUDE.md・AGENTS.mdは整備済み

図解

夜間に動画自動生成 → 作業報告を別AIが監視 → 危険サインだけ通知 → 翌朝に確認・判断

提言夜間動画生成の監視にこのプラグインを試す

  1. 対応バージョンとテレメトリー設定の条件を先に確認する
  2. /plugin enableで有効化し夜間の動画生成実行に適用してみる
  3. 二重実行・誤送信などの危険報告ルールを試験的に検証する
  4. 翌朝の確認作業に「了解・相談・閉じる」の判断を組み込む
いま夜間無人実行の失敗や危険は翌朝まで気づけない
→
実行後危険な兆候だけ先に知らせてもらえる仕組みになる

CASE 03 ／ 販売幕僚

スターリンク紹介プログラム検証

要点スターリンクの紹介で報酬がもらえる仕組み

衛星インターネット「スターリンク」が、紹介リンクを共有した人に現金やサービス利用クレジットを渡すプログラムを始めました。友達に1か月無料も贈れます。N's factoryがこの仕組みを紹介料収入（アフィリエイト）として使えるか検討します。

現状分析アフィリ運用の下地はあるが未検証

  • 型紙PDF関連の注意点に『アフィリエイトは必要な表示・表記を確認する』とある
  • 商品ページを信頼されやすい順（結論→体験→弱点→おすすめ）で書く型が社内にある
  • スターリンク紹介プログラム自体の規約・商用利用可否はまだ確認していない

図解

公式規約を確認 → 商用利用可否を判定 → PR表記ルールを確認 → 紹介記事を作成

提言規約確認を先に済ませてから判定する

  1. 公式の利用規約で商用利用の可否を確認する
  2. 景品表示法（ステマ規制）に沿ったPR表記ルールを確認する
  3. 可の場合は『結論→体験→弱点→おすすめ』の型で紹介記事を作る
  4. 不可の場合は見送り、別のアフィリ候補を探す
いまアフィリ候補として未検証のまま止まっている
→
実行後規約確認済みで実施可否を判断できる状態になる

CASE 04 ／ 広報幕僚

SNS投稿の6項目事前準備フロー

要点AIに頼む前に6項目を決める

SNSの投稿文をAIに書かせる前に、まず「分野・読者・目標・口調・形式・使える時間」の6つを自分で決めて伝える。そのあとで30日分の投稿予定を作り、最後に個別の文章をAIに書かせる、という順番にする方法です。

現状分析投稿準備は型化されていない

  • 複数SNSを発信中だが一部自動・一部手動で運用がバラバラ
  • ハッシュタグやブランド素材の管理はあるが投稿前の準備シートは見当たらない
  • 30日分の投稿予定をまとめて作る仕組みは確認できない

図解

6項目シート記入 → 30日分の予定作成 → AIに個別文章作成依頼 → 各SNSへ投稿

提言投稿前に6項目シートを使う

  1. 分野・読者・目標・口調・形式・時間の6項目を記入するシートを作る
  2. 月初に30日分の投稿予定を先にまとめて作成する
  3. 3つのプラットフォームそれぞれに同じ型を使い回して効率化する
  4. 個別の投稿文章はこの型をもとにAIへ依頼する
いま投稿ごとに毎回ゼロから文章を考えている
→
実行後6項目と30日予定をもとに迷わず書ける

CASE 05 ／ 広報幕僚

Geminiで工房写真から短編PR動画

要点写真1枚でPR動画を作るAI技術

Googleの動画生成AI「Gemini」に、お店の写真1枚と短いカメラの動かし方の指示を送るだけで、短いPR動画が作れる機能です。「周りをぐるっと回る」「遠くから近づく」などの指示コマンドが複数公開されています。有料プラン限定の可能性があり、先に条件確認が必要です。

現状分析SNS発信は手動中心

  • 複数のSNSを運用し、一部は自動投稿、一部は手動投稿で回している
  • Instagramは転載中心だとおすすめに出にくい方針があり、オリジナル投稿が必要
  • ハッシュタグ運用やロゴ等のブランド素材管理も担当している

図解

工房・商品の写真1枚 → カメラ指示コマンドを指定 → Geminiが短編動画を生成 → Instagramリールへ投稿

提言Gemini動画でリール量産を試験

  1. 有料プランの条件を確認し、無料版との違いを把握する
  2. 工房写真1枚でテスト動画を1本作成してみる
  3. オリジナル動画として投稿し、おすすめ表示との関係を確認する
  4. 月4本の試験投稿を行い、保存・反応の変化を記録する
いま写真投稿や手作業での動画編集が中心
→
実行後写真［数値］から短編PR動画を試験的に量産できる

CASE 06 ／ デジタル幕僚

LPボタン文言と高さ最適化

要点ボタンの言葉と大きさを見直す

LPのボタンは「送信」より「無料で資料を受け取る」のように押すと何が起きるか分かる言葉の方が反応が良い。スマホでは高さ44px以上が押しやすい目安。まず1つのボタン文言を書き換えてみる提案です。

現状分析ボタン文言は場所ごとにばらつき

  • AI接客体制ではPhase2でボタン文言統一を一度実施済み
  • 第3セット講座は商品シート反映まで購入ボタンが「メールで購入を申し込む」表示のまま
  • 型紙PDF販売は販売ページ文言・EC出品文が準備領域として挙がっている
  • 高さ44px確認についての記載は社内資料に見当たらない

図解

before

  • ボタン文言「詳しくはこちら」「送信」など

after

  • 「型紙PDFを購入する」など動詞＋得られ

提言EC・講座ページのボタンを動詞＋得られるもの文言に

  1. 商品ページのボタンを「型紙PDFを購入する」に変更する
  2. 講座ページの「メールで購入を申し込む」も具体的な動詞文言に見直す
  3. スマホ表示でボタンの高さが44px以上あるか確認する
  4. 効果が出た文言パターンを他のEC出品先にも横展開する
いまボタン文言はページごとにばらつきがある
→
実行後動詞＋得られるものの文言に統一され押しやすくなる
