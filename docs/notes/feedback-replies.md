# 改善要望への返信の書き方

公開ツールの「💡 改善要望」ボタンは、送った人の端末に要望の冒頭を保存し、
`assets/feedback-replies.json` と突き合わせて「開発者からの返信」を表示する。GAS・スプレッドシートの操作は不要。
返信は Claude に「この要望にこう返信して」と頼めば、このファイルに追記して main へ反映する（スマホだけで完結）。

## 形式
```json
{
  "replies": [
    { "match": "紙の短い辺の方に穴", "page": "a6-daily/index.html", "reply": "ありがとうございます。短辺（上）の穴を追加しました。", "replyAt": "2026-10-23", "done": true }
  ]
}
```
- `match`（必須）: 要望の文中にそのまま含まれる言葉。要望の冒頭120文字に入っていること。短すぎると別の要望に当たる
- `page`（任意）: 指定するとそのツールからの要望だけに当たる。例 `a6-daily/index.html`
- `reply`（必須）: 返信の文章
- `replyAt`（任意）: `2026-10-23` の形。新着の判定に使う。返信を書き換えたら日付も新しくする
- `done`（任意）: true で「✓ 対応済み」（返信文がないときだけ表示される）

## 改善要望の状況（board）— ツールを開いたときに見える一覧
同じファイルの `board` に書くと、そのツールの「改善要望」ボタンの中に状況の一覧が出る。要望を送っていない人にも見える。
状況が変わる（`status` か `updatedAt` が変わる）と、そのツールを開いたときにボタンへ赤い数字が出る（更新から30日以内のものだけ）。

```json
"board": [
  { "page": "a6-daily/index.html", "title": "紙の短い辺（上端）に穴を開けたい", "status": "確認中", "note": "…", "updatedAt": "2026-10-25" }
]
```
- `page`（必須）: ツールのパス。そのツールの画面だけに出る
- `title`（必須）: 要望の要約。個人を特定できる内容は書かない
- `status`（任意）: 受付済み／確認中／検討中／対応中／一部対応／対応済み／見送り（色が付く。他の言葉も可）
- `note`（任意）: 一言の説明
- `updatedAt`（任意）: `2026-10-25` の形。状況を変えたら新しくする
- `id`（任意）: 題名を直しても同じ項目として扱いたいときに付ける

## 注意
- このファイルは公開される。名前・連絡先など個人情報は書かない。`match` にも入れない
- 要望を送った時点で冒頭が端末に残る仕組みなので、この機能の公開前に送られた要望には返信が出ない
- 同じ要望に複数当たったときは、`replyAt` が新しい返信を採用する
