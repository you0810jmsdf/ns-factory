# AI経営奮闘記（AI日記）生成ポリシー v1.0

最終更新: 2026-07-28 / 起案: 後方幕僚・広報幕僚

## 0. このファイルの位置づけ

AI日記の生成処理はローカル保管庫側にあり、本リポジトリには含まれない。
本ファイルは**生成ルールの正本**として GitHub に置き、ローカル側の指示書へ同じ内容を反映する。

| 役割 | ファイル |
|------|---------|
| ルール正本（本ファイル） | `docs/ai-diary-generation-policy.md`（ns-factory） |
| 生成指示書 | `後方部\AI日記自動化\指示書.md` |
| 日次出力 | `後方部\AI日記自動化\output\YYYY-MM-DD_diary.md` |
| 掲載手順 | `経営戦略本部\AI日記note自動掲載_引き継ぎ書.md` |
| 掲載方針 | `広報部\note広報_指示書.md` |

## 1. 課題（改訂の理由）

- 2026-03-09 以降、**作業実績の有無にかかわらず毎日1本**を生成し続けている。
- その結果、素材が無い日は一般論・決意表明・前日の焼き直しで字数を埋めており、
  読み手には「毎日内容が変わらない」「無理やり書いている」と映る。
- 連続投稿日数は KPI ではない。読む価値のある回だけを出す方が連載の価値は上がる。

## 2. 大原則

> **素材が無い日は、書かない。**

生成ルーチンの既定動作を「毎日1本書く」から「**素材を判定し、足りなければ不掲載**」に変更する。
不掲載はエラーでも失敗でもなく、正常な結果として扱う。

## 3. 掲載可否の判定

### 3-1. 素材ソース（当日分のみ走査）

1. `監理部\業務日誌.md` の当日エントリ
2. ns-factory リポジトリの当日コミット（ドキュメント整形・数値更新の自動コミットは除く）
3. 受注・発送・見積の動き（販売部）
4. 仕入・原価・入出金の動き（監理部）
5. 幕僚計画カレンダーで当日 status が「完了」になったタスク
6. 外部からの反応（問い合わせ、SNS 反応、教室・マルシェでの出来事）
7. 失敗・トラブル・意思決定の記録

### 3-2. 「素材1件」の定義

次の**両方**を満たすものだけを1件と数える。

- 当日に**実際に起きた事実**であること（構想・予定・感想は素材ではない）
- **数字か固有名詞を1つ以上伴う**こと（商品名・革名・ページ名・金額・件数・型番など）

### 3-3. しきい値

| 素材件数 | 判定 |
|---------|------|
| 0〜1件 | **不掲載**（週次まとめへ繰り越し） |
| 2件以上 | 掲載可。ただし §4 の重複チェックを通ること |

自動集計スクリプトの `--min-materials` は既定 `2`。運用しながら調整してよいが、`0` にはしない。

## 4. 重複チェック

- 直近**7日分**の diary から主題キーワードを抽出し、主題が一致する素材は「新規素材」に数えない。
- 主題が同じでも「前回から進んだ差分」がある場合のみ可（例: 前回=着手 → 今回=公開）。
- 重複除外の結果、素材が2件未満になったら不掲載に落とす。

## 5. 執筆ルール（「無理やり感」の除去）

### 5-1. 禁止

- 定型の締め文。以下は使用禁止:
  「今日も一日」「改めて感じた」「小さな一歩」「引き続き頑張っていきたい」
  「地道に続けていくしかない」「明日も前に進む」
- 毎回同じ見出し構成（固定テンプレートの使い回し）。見出しはその日の内容から起こす。
- 一般論・AI論・精神論だけで構成された回。
- 字数合わせのための言い換え反復、素材の水増し。

### 5-2. 必須（自己検証チェックリスト）

出力前に生成側で確認し、1つでも欠けたら**不掲載に落とす**。

- [ ] 数字が1つ以上入っている
- [ ] 固有名詞が1つ以上入っている（商品名・革名・ページ名・ツール名など）
- [ ] 前日の結論文と実質同義になっていない
- [ ] 「その日でなければ書けない具体」が本文中に1箇所以上ある
- [ ] 素材を削っても文意が通る段落（＝水増し段落）が無い

### 5-3. 分量

- 目安 800〜1,500字。素材が2件しかない日は**短くてよい**。
  字数下限のために書き足さない。

## 6. 不掲載日の扱い

- `output\` に空ファイルやプレースホルダを作らない（後段の掲載処理が拾わないようにするため）。
- 掲載処理側は、当日ファイルが存在しないことを正常終了として扱う。
- ログにのみ記録する。書式:

```
## YYYY-MM-DD AI日記ルーチン
- 判定: 不掲載
- 理由: 素材0件（業務日誌に当日エントリなし）
- 繰り越し: なし
```

掲載した日は `- 判定: 掲載` と採用素材の一覧を残す。

## 7. 週次まとめへの繰り越し

- 不掲載日の素材（1件だけあった日など）は破棄せず、週次まとめの候補として保持する。
- 日曜に、直近7日の未使用素材を集約して1本にまとめる。ここでも素材2件未満なら出さない。
- 想定ペースは **週2〜3本**。毎日投稿は目標としない。

## 8. ローカルへの反映手順

1. `後方部\AI日記自動化\指示書.md` を開く。
2. 「毎日1本生成する」旨の記述を、本ファイル §2〜§7 の内容で置き換える。
3. 生成スクリプトに素材判定を追加する（判定結果が不掲載なら出力ファイルを作らずログのみ）。
4. `経営戦略本部\AI日記note自動掲載_引き継ぎ書.md` の掲載処理に、
   「当日ファイルが無い場合は正常終了」を明記する。
5. 反映後、本ファイルの最終更新日を更新する。
