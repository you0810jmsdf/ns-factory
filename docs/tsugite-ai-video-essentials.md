# tsugite 分析 — AI動画作りに必要なエッセンス

対象: https://github.com/Takamasa045/tsugite （2026-07-18 時点の内容を確認）

## 1. tsugite とは何か

tsugite は「生成AI動画エンジン（PixVerse / Kling / Seedance など）」と「編集バックエンド（Remotion / HyperFrames）」を、`project.yaml` + `manifest.json`（EDL＝Edit Decision List）という単一の契約でつなぐ、ベンダー中立の動画パイプラインです。

- 生成エンジン N 個 × 編集手段 M 個を **N×M の個別統合ではなく N+M のアダプタ** で吸収する設計（`adapters/`＝生成・解析、`backends/`＝編集）。
- コア（`src/`）はどの外部ベンダーの名前も持たず、ベンダー固有処理は必ず `adapters/` か `backends/` に閉じ込める（`vendorBoundary.ts` で機械強制）。
- 動画1本＝1 `project.yaml`。ユーザーの作業ファイルは `projects/`（gitignore）に置き、`examples/` はコピー用サンプルとして repo に残す。

このリポジトリ自体が動画を自動生成する「魔法のツール」ではなく、**「良い動画を安全に・再現性高く作るための工程管理と知識ベース」**である点が最大の特徴です。AI動画生成そのものより、その前後（企画・承認・検証）に重心があります。

## 2. 基本フロー（安全設計の骨格）

```
project/manifest 検証 → 実行計画作成 → Gate 1（人間承認）
  → 生成 or 組み立て → Gate 2（出力QC）
  → render → Gate 3（最終動画QC）
```

- `run` と `render`（課金・実行を伴う操作）は **明示的な人間承認（Gate）なしには実行できない** ように意図的にブロックされている。
- Gate 2 は生成された各クリップの QC（`approve_all` のみ実装、部分差し替えの `retry_specific` は未実装で曖昧な成功をさせない）。
- Gate 3 は最終 MP4 の尺・解像度・fps・映像/音声ストリームを機械検査。
- `analyze`（文字起こし・フィラー検出・章立て・要約）は元素材や manifest を一切変更せず、候補を出すだけ。人間が `edit.editorial` で明示選択し、Gate 1 承認後の `run` だけが反映する。

**エッセンス**: AI動画は「生成→即採用」ではなく、各段階に人間のチェックポイントを置き、生成・組み立て・レンダリングという「後戻りしにくく・コストがかかる操作」の前に必ずゲートを挟む設計が事故防止の核。

## 3. 物語構成・尺設計の知識（`knowledge/story-frameworks/catalog.yaml`）

34種類の構成テンプレートを、用途・尺（short_form_score / long_form_score）・注意点付きでカタログ化。代表例:

| 型 | 用途 | 構成 |
|---|---|---|
| Hook Value Proof CTA | 縦型SNS・短尺広告 | Hook→Value→Proof→CTA |
| AIDA | 広告・集客 | Attention→Interest→Desire→Action |
| PAS | 悩み訴求 | Problem→Agitate→Solution |
| Before After Bridge | 改善事例・導入実績 | Before→After→Bridge |
| 起承転結／三幕構成／ヒーローズジャーニー抽象型 | 物語性のある動画 | 定番の物語構造を抽象化 |
| オープンループ型 | 短尺解説・リビール | 未解決の問い→部分情報→期待更新→回収 |

さらに **尺別のカット数・時間配分プリセット** を持つ：

- 15秒: 3〜5カット（Hook 0-2s／文脈／価値・実例／CTA・余韻）
- 30秒: 5〜7カット
- 60秒: 8〜12カット
- 90秒: 12〜18カット
- 長尺: 16〜40カット（%配分）

**エッセンス**: 「何となく良い動画」ではなく、**尺が決まった瞬間にカット数と各カットの役割（Hook/文脈/価値/CTA等）が決まる**という発想。企画段階で構成テンプレートと尺プリセットを先に選び、そこにカット内容を当てはめる。

## 4. 映像文法・編集原則（35項目）

`catalog.yaml` の `principles` に、AI動画生成を前提にした撮影・編集・音の原則がまとまっている。特に重要なもの:

**カット設計**
- 1カット1情報・1動作・1感情（one-shot-one-role）
- 各カットに「開始状態・可視の変化・終了状態」を明記する（start-end-state）
- 生成クリップは主動作・主カメラ移動をそれぞれ1つに絞る（one-motion-per-clip）— AI生成の破綻防止に直結
- カメラ移動は被写体の動き・情報開示・感情変化に動機づける（camera-motivation）

**AI生成特有の連続性対策**
- 複数クリップ間で人物特徴・衣装・光の向き・画面方向を固定して使い回す（continuity-anchor）
- 各生成クリップの始点・終点に編集用の安定フレームを確保する（transition-handles）
- 参照画像は外見・空間を担当、テキストは動作・時間変化を担当と役割分担する（reference-ownership）＝ 後述のプロンプト知識と直結

**連続性（Continuity）**
- 180度ルール（screen-direction）、視線の一致（eyeline-match）、マッチ・オン・アクション、切り返し（shot-reverse-shot）、確立ショット（establishing-reestablishing）

**構図**
- 三分割法、リーディングライン、ルックルーム、ヘッドルーム、奥行き（前景・中景・背景）、視覚的階層は1つだけ優先順位を決める

**音**
- J/Lカットで音と画をずらす、ダイアログダッキング、ルームトーン、静寂による強調、音のモチーフ

**エッセンス**: これらは映画理論の抽象化だが、「AI生成クリップ同士をどう自然に繋ぐか」という現代的な課題（continuity-anchor, transition-handles, one-motion-per-clip）を明示的に加えている点が実務的に価値が高い。

## 5. モデル別プロンプト設計知識（PixVerse / Kling / Seedance）

3モデル共通で見えてくる原則:

1. **主語・行動・場所を先に、装飾語を後に**（lead-with-control）。"cinematic" "high quality" のような抽象語より、レンズ・光・パレット・構図の具体的な視覚手がかりを使う。
2. **1クリップ＝1カメラワーク**。複数のカメラ移動を同時に指示しない（one-camera-vector / one-camera-per-shot）。
3. **T2V と I2V でプロンプトの役割が違う**:
   - Text-to-Video: `[被写体][1つの動作][場所]。[1つのカメラワーク]＋[具体的スタイル]。[安定した終了状態]。`
   - Image-to-Video: 参照画像が外見・構図・背景を担うので、**再描写せず「時間変化」だけを書く**（do-not-redescribe）。変わらない性質を1つだけ明示する（preserve-identity）。
4. **ネガティブプロンプトはモデルごとに扱いが違う**ので、専用フィールドがなければ「除外」ではなく「望む状態を肯定文で書く」のが安全（例: PixVerse/Kling は基本 positive-constraints、Seedance は文末に短い除外を書く）。
5. **モデル制約はAPI仕様と実装（adapter）で食い違うことがある**ので、鮮度管理（`verified_at` / `review_after`）を持ち、実行時は実際のCLI/API制約を優先する。

**エッセンス**: 良いAI動画プロンプトは「詩的な長文」ではなく、**主語→1動作→場所→1カメラ移動→具体的な視覚ディテール→終了状態の安定** という決まった順序のテンプレートに近い。参照画像がある場合は「画像が担当する情報」と「テキストが担当する情報」を重複させないことが最重要。

## 6. 継続的な改善ループ（フィードバックの仕組み）

- 出力を見た結果を `pipeline feedback` で `projects/<job>/feedback.jsonl` に記録。
- 状態遷移: `observed`（1回限りの気づき）→ `recurring`（同じ key で反復確認）→ `promoted`（ルール・テンプレへ反映済み）→ `verified`（後続出力で改善確認）。
- 反復が確認できたら「昇格案」（pending→approved/rejected）を作り、**人間が必ず承認**してから repo のルール・テンプレ・チェックへ反映する（自動反映はしない）。
- 昇格先の目安表: 一度きりの好み→メモ、反復する好み→feedback、頻出パターン→examples/templates、機械的に防げる失敗→validate/doctorのチェック、判断ルール→運用ドキュメント、QA基準→Gate 2/3のチェック。

**エッセンス**: 「なんとなく前回より良くなった気がする」を防ぐために、同じ問題を示す `key` を使って反復を検知し、反復が確認できて初めて恒久ルール化する、という一段構えの仕組み。

## 7. ns-factory（SNS動画メーカー）への示唆

`digital-room/sns-video-maker/`（写真ベースの縦型SNS動画をブラウザ内で生成するツール）は、生成AI動画エンジンではなく写真＋ナレーション＋テロップのスライドショー型ですが、tsugite の知見はそのまま応用できます。

- **尺プリセット×カット数の考え方**を写真の枚数・切り替えタイミング設計に流用できる（例: 30秒動画なら5〜7カット相当の構成に区切り、冒頭2〜3秒をHookに使う）。
- **1カット1情報の原則**は、1枚の写真に載せる説明文・テロップを1メッセージに絞る指針として使える。
- **開始状態→変化→終了状態**の考え方は、写真の並び順（Before/After、工程順）の設計に転用できる。
- **物語構成カタログ（Hook Value Proof CTA、Before After Bridge、AIDA など）**は、そのまま商品紹介動画の構成テンプレートとして採用候補になる。
- 将来 PixVerse/Kling 等の生成AIを組み込む場合は、tsugite のプロンプトテンプレート（主語→1動作→場所→1カメラ→終了状態の安定）と Gate 型承認フローがそのまま参考になる。

## 8. まとめ：AI動画作りに必要なエッセンス（要約）

1. **企画を型に落とす**: 目的・尺から構成テンプレートとカット数・役割配分を先に決める。
2. **1カット1役割**: 情報・動作・感情を1つに絞り、開始/終了状態を明記する。
3. **プロンプトは構造化する**: 主語→1動作→場所→1カメラワーク→具体的視覚ディテール→安定した終了状態。参照画像とテキストの役割を重複させない。
4. **AI生成特有の継ぎ目対策**: 連続性アンカー（外見・光・向きの固定）と編集用の安定フレームを確保する。
5. **人間の承認ゲートを工程に埋め込む**: 生成・組み立て・レンダリングという「戻せない／コストがかかる」操作の前には必ず人間チェックを置く。
6. **フィードバックを仕組み化する**: 一度きりの気づきと反復するパターンを区別し、反復が確認できたものだけルール・テンプレへ昇格する。
